# SPEC.md — AI Mystery Room Specification

## Document Overview
- **Project**: AI Mystery Room
- **Purpose**: A web-based interactive mystery game where players investigate cases procedurally generated by Google Gemini AI, inspect suspect dossiers, uncover forensic clues, leverage hints, and accuse the culprit.
- **Author**: Antigravity & Lead Engineer
- **Status**: Approved Blueprint for Implementation

---

## A. Project Requirements

### 1. Overview & Problem Statement
Traditional murder mystery and detective games rely on pre-scripted static storylines that offer zero replayability once solved. Handcrafted interactive fiction is costly and slow to produce. **AI Mystery Room** bridges this gap by leveraging generative AI (Google Gemini) to dynamically craft logically coherent, narrative-rich whodunit mysteries tailored to player preferences and selected difficulty levels.

### 2. Target Users & Expected Experience
- **Target Audience**: Mystery fans, puzzle enthusiasts, casual gamers, and interactive fiction readers.
- **User Experience**:
  - Atmospheric noir / detective aesthetic with high-contrast typography, evidence cards, and suspenseful visual cues.
  - Smooth, intuitive interactions: one-click clue inspection, suspect interrogation profiles, and clear deduction paths.
  - Zero spoilers: The solution remains strictly quarantined on the backend until formal accusation.
  - Responsive, fast, and resilient against AI generation anomalies.

### 3. Core Features
1. **Dynamic Case Generation**: Creates varied mystery scenarios across themes (victorian manor, cyberpunk heist, modern corporate espionage, art gallery theft, locked-room murder) based on user prompt or presets.
2. **Difficulty Tiers**:
   - **Easy**: 3 Suspects, 5 Clues, 2 Hints.
   - **Medium**: 4 Suspects, 7 Clues, 3 Hints.
   - **Hard**: 5 Suspects, 9 Clues, 3 Hints.
3. **Investigation Dashboard**:
   - Suspect Dossiers (name, occupation, alibi, motive, demeanor).
   - Evidence Locker / Clue Board (discoverable clues that unlock forensics upon inspection).
   - Clue & Hint Progress Trackers.
4. **Hint Hotline**: Players can request up to the maximum difficulty-allowed hints at a score penalty.
5. **Accusation Confrontation**: Player reviews their gathered intelligence and formally accuses one suspect.
6. **Case Closed & Verdict**:
   - Full debriefing revealing the true culprit, the motive, how the crime was executed, which clues proved guilt, and a detailed score breakdown.
   - Replayability: One-click option to embark on a new investigation.

### 4. Optional Enhancements & Polish
- Preset mystery templates for quick play without typing.
- Ambient detective noir theme with badge iconography (using Lucide icons).
- Sound/visual feedback animations when uncovering clues or reaching high scores.
- Copy case report / shareable scorecard.

### 5. Technology Stack
- **Frontend**:
  - React 18+ with Vite
  - Tailwind CSS for modern responsive styling
  - React Router v6 for client-side navigation
  - Axios for API communication
  - Lucide React for detective and crime scene icons
- **Backend**:
  - Node.js (v20+) with Express
  - MongoDB with Mongoose ORM
  - Google Gemini API (`@google/genai` or `@google/generative-ai`)
  - Zod for strict runtime schema validation of AI outputs and API payloads
  - CORS and Dotenv for cross-origin security and config management

### 6. Limitations & Constraints
- Culprit identity and explanation **must never** be sent over the wire prior to a POST `/api/cases/:id/accuse` submission.
- Gemini responses must strictly adhere to valid JSON with enforced fallback/retry handling.
- Minimum player score cannot drop below 0.

## D. Backend and Database Design

### 1. Database Model (`Case` Schema)

```typescript
interface ISuspect {
  id: string;              // e.g. "suspect_1"
  name: string;
  role: string;
  alibi: string;
  motive: string;
  demeanor: string;
}

interface IClue {
  id: string;              // e.g. "clue_1"
  title: string;
  description: string;
  isDiscovered: boolean;
  discoveredAt?: Date;
}

interface IHint {
  id: string;              // e.g. "hint_1"
  hintText: string;
  isRevealed: boolean;
  revealedAt?: Date;
}

interface ICase {
  title: string;
  premise: string;
  story: string;
  difficulty: 'easy' | 'medium' | 'hard';
  suspects: ISuspect[];
  clues: IClue[];
  hints: IHint[];
  
  // SECURE FIELDS (Excluded from GET /api/cases/:id before accusation)
  culpritId: string;
  culpritName: string;
  solutionExplanation: string;
  
  // GAMEPLAY STATE
  status: 'investigating' | 'completed';
  score: number;
  accusedSuspectId?: string;
  isAccusationCorrect?: boolean;
  createdAt: Date;
  completedAt?: Date;
}
```

### 2. API Endpoints Contract

#### 1. `POST /api/cases`
- **Description**: Generates a new mystery using Gemini AI, saves to MongoDB, and returns sanitized case data.
- **Request Body**:
  ```json
  {
    "premise": "A priceless diamond necklace vanishes during an aristocratic gala at Midnight Manor.",
    "difficulty": "medium"
  }
  ```
- **Response `201 Created`**:
  ```json
  {
    "success": true,
    "case": {
      "_id": "6724...",
      "title": "The Phantom of Midnight Manor",
      "premise": "...",
      "story": "...",
      "difficulty": "medium",
      "suspects": [
        { "id": "suspect_1", "name": "Lord Sterling", "role": "Host", "alibi": "...", "motive": "...", "demeanor": "..." }
      ],
      "clues": [
        { "id": "clue_1", "title": "Velvet Glove near Vault", "description": "...", "isDiscovered": false }
      ],
      "hints": [
        { "id": "hint_1", "hintText": "Check the timestamp on the library log", "isRevealed": false }
      ],
      "status": "investigating",
      "score": 0
    }
  }
  ```
  *(Note: `culpritId`, `culpritName`, and `solutionExplanation` are strictly omitted)*

#### 2. `GET /api/cases/:id`
- **Description**: Fetches the active case. Returns the full case sanitized if `status === 'investigating'`, or full case with solution if `status === 'completed'`.
- **Response `200 OK`**: Sanitized case object.

#### 3. `POST /api/cases/:id/clues/:clueId/discover`
- **Description**: Marks a specific clue as discovered.
- **Scoring**: Adds `+5` points to case score.
- **Response `200 OK`**:
  ```json
  {
    "success": true,
    "clue": { "id": "clue_1", "title": "Velvet Glove", "description": "...", "isDiscovered": true },
    "score": 5
  }
  ```

#### 4. `POST /api/cases/:id/hints`
- **Description**: Reveals the next unrevealed hint in sequence.
- **Scoring**: Deducts `10` points (floor at 0).
- **Validation**: Checks if remaining hints exist under the difficulty quota.
- **Response `200 OK`**:
  ```json
  {
    "success": true,
    "hint": { "id": "hint_1", "hintText": "...", "isRevealed": true },
    "hintsRemaining": 2,
    "score": 0
  }
  ```

#### 5. `POST /api/cases/:id/accuse`
- **Description**: Submits the final accusation. Evaluates correctness, computes final score, reveals culprit and solution explanation, and transitions `status` to `completed`.
- **Request Body**:
  ```json
  {
    "suspectId": "suspect_2"
  }
  ```
- **Scoring Algorithm**:
  - `basePoints = isCorrect ? (difficulty === 'easy' ? 100 : difficulty === 'medium' ? 150 : 200) : 0`
  - `clueBonus = discoveredCluesCount * 5`
  - `hintPenalty = revealedHintsCount * 10`
  - `finalScore = Math.max(0, basePoints + clueBonus - hintPenalty)`
- **Response `200 OK`**:
  ```json
  {
    "success": true,
    "isCorrect": true,
    "culpritId": "suspect_2",
    "culpritName": "Lady Genevieve",
    "solutionExplanation": "Lady Genevieve used the replica key to swap the diamond...",
    "scoreBreakdown": {
      "basePoints": 150,
      "cluesBonus": 25,
      "hintsPenalty": 10,
      "finalScore": 165
    }
  }
  ```

#### 6. `GET /api/cases/:id/result`
- **Description**: Returns the finalized result debrief for a completed case.

## E. AI Behavior and Scoring Rules

### 1. Difficulty Matrix
| Difficulty | Suspects | Clues | Hints | Base Accusation Pts |
| :--- | :---: | :---: | :---: | :---: |
| **Easy** | 3 | 5 | 2 | 100 |
| **Medium** | 4 | 7 | 3 | 150 |
| **Hard** | 5 | 9 | 3 | 200 |

### 2. Scoring Formula
$$\text{Final Score} = \max\Big(0,\; \text{BaseAccusationPts} + (\text{DiscoveredClues} \times 5) - (\text{HintsUsed} \times 10)\Big)$$
- Correct Accusation:
  - Easy: `+100`
  - Medium: `+150`
  - Hard: `+200`
- Incorrect Accusation: `0` base points.
- Each Clue Discovered: `+5` points.
- Each Hint Used: `-10` points.
- Floor: Cannot be negative (min 0).

### 3. Gemini Prompt Engineering & Zod Validation
The backend enforces structured JSON output using Gemini's JSON mode (`responseMimeType: "application/json"` or schema):
- Prompt guarantees:
  1. Exactly 1 true culprit who is included in the `suspects` list.
  2. Every suspect has a plausible alibi and motive to prevent obvious trivial deductions.
  3. Clues contain subtle forensic evidence (fingerprints, receipts, discrepancies in timeline) that logically point to the true culprit and rule out innocent suspects.
  4. Structured response validated by Zod schema before database persistence.

## F. Acceptance Criteria

- [x] **Generation**: User can create a mystery by providing a premise and difficulty (Easy, Medium, Hard).
- [x] **Difficulty Scaling**: AI generates the exact quota of suspects (3/4/5), clues (5/7/9), and hints (2/3/3).
- [x] **Information Security**: Neither `culpritId`, `culpritName`, nor `solutionExplanation` are leaked in frontend payloads prior to accusation.
- [x] **Clue Discovery**: Clues start hidden/locked and can be unlocked individually, adding +5 points each.
- [x] **Hint System**: Hints can be unlocked sequentially, deducting 10 points per hint, with counter updating accurately.
- [x] **Accusation & Verdict**: Accusing a suspect triggers backend evaluation, returns win/loss status, reveals true culprit, and displays narrative explanation.
- [x] **Scoring**: Backend calculates score strictly based on the scoring matrix with floor 0.
- [x] **Replayability**: Users can restart or generate a fresh mystery anytime.
- [x] **UI & Responsive UX**: Modern, atmospheric noir responsive interface with clear loading states and error toasts.
- [x] **Production Readiness**: Separation of concerns with client/server, `.env` configuration, clean API routes.
